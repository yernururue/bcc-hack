# ReqCheck

**ИИ-агент статического ревью документов требований.** Агент берёт готовый документ (PDF, Markdown, TXT, DOCX), режет его на отдельные требования и проверяет каждое из них и весь набор целиком по ISO/IEC/IEEE 29148:2018 (п. 5.2.5, 5.2.6) и IEEE 830-1998 (п. 4.3). Результат — отчёт на русском с ответом на главный вопрос: **можно ли начинать разработку и тестирование**.

Хакатон BCC-HUB x MNU FinTech.

> Каждая находка опирается на цитату, которую **код** нашёл в тексте документа. Находка без проверенной цитаты в отчёт не попадает. Вердикт и счётчики тоже считает код, по правилам из `config/thresholds.yaml`, а не модель.

## Быстрый старт

Нужен Python 3.12+. Рекомендуем [uv](https://docs.astral.sh/uv/).

**1. Установка**

```bash
uv sync --all-extras
```

Без uv: `python3.12 -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt`.

**2. Ключ LLM**

1. Получите ключ на [openrouter.ai/keys](https://openrouter.ai/keys). Прогон документа на 10 страниц на модели по умолчанию стоит центы.
2. Скопируйте пример конфига и впишите ключ в строку `LLM_API_KEY=`:

```bash
cp .env.example .env
```

Файл `.env` в git не попадает. Подойдёт любой OpenAI-совместимый API. Для другого провайдера или шлюза банка задайте в `.env` ещё `LLM_BASE_URL` и `LLM_MODEL`.

**3. Прогон одной командой: файл требований и файл отчёта**

```bash
uv run python main.py docs/before/requirements.md out/review.md
```

- Отчёт ляжет в `out/review.md`, рядом всегда пишется машиночитаемый `out/review.md.json`.
- Формат отчёта берётся из расширения: `.md`, `.pdf`, `.docx` или `.json`. Без расширения формат совпадает с входом.
- Перед прогоном агент печатает оценку стоимости. `--dry-run` только разбирает документ и показывает оценку, модель не вызывается.
- `--max-cost USD` — предохранитель: на лимите прогон останавливается, а отчёт помечается неполным.
- Ответы модели кэшируются в `.cache/reqcheck`, так что повторный прогон того же документа бесплатный и даёт тот же отчёт. `--no-cache` спрашивает модель заново.

Модель по умолчанию — `openai/gpt-6-luna`: она лучшая среди дешёвых по нашему eval. Другую модель задаёт `--model <id>`, список с ценами лежит в `config/models.yaml`. Все флаги: `uv run python main.py -h`.

## Что в отчёте

Разделы отчёта соответствуют разделу 6 ТЗ:

1. **Паспорт прогона:** документ и его SHA-256, дата, модель, версия агента, вызовы, токены, стоимость, стандарты.
2. **Как агент нарезал требования:** ID в отчёте, ID в документе, тип, краткая формулировка и место. Если номеров в документе нет, агент присваивает свои и сохраняет цитату.
3. **Проверка каждого требования** по 9 характеристикам 29148: однозначность, полнота, единичность, выполнимость, проверяемость, корректность, необходимость, свобода от реализации, соответствие.
4. **Проверка всего набора:** противоречия, пробелы в темах, дубли, разнобой терминов, трассируемость.
5. **Сводка:** число требований, нарушения по серьёзности, критичные дефекты.
6. **Вопросы к автору:** варианты ответа, влияние и допущение на случай, если ответа не будет.
7. **Итог:** можно ли начинать разработку и тест-дизайн, топ-5 исправлений и правило, по которому код принял решение.

У каждой находки есть место (раздел › пункт, страница или строка), дословная цитата, объяснение и предложение, как исправить.

## Почему отчёту можно верить

| Механизм | Как работает |
|---|---|
| Цитату проверяет код | Модель обязана процитировать документ. Код ищет цитату в тексте нечётким сравнением с порогом из `config/thresholds.yaml`. Если не нашёл, находка уходит в `debug.dropped_findings` JSON-отчёта, а не в отчёт |
| Вердикт считает код | «Нельзя начинать разработку», если blocker ≥ 1; «с оговорками», если major ≥ 3. Правило печатается в разделе 7 |
| Противоречия подтверждаются | Отдельный короткий вызов перепроверяет каждое заявленное противоречие. Пары, признанные совместимыми, уходят в debug |
| Пустые ответы не прячутся | Если модель вернула находки без цитат и пояснений, вызов повторяется. Повторный пустой ответ помечает отчёт неполным, а не выдаёт «дефектов нет» |
| Воспроизводимость | Кэш ответов: тот же документ, модель и промпт дают тот же отчёт |
| Инъекции в документе | Текст документа передаётся модели как данные внутри `<document>`, системный промпт запрещает выполнять инструкции из него |

## Как это работает

```
документ → ingest → extract → rules → check_each → check_set → confirm → verify → фильтр шума → questions → verdict → render
           код      LLM       код     LLM, батчи   LLM         LLM       код      код            LLM         код       код
```

- **ingest** разбирает документ на блоки с якорями: разделы, пункты, таблицы, страницы PDF (pymupdf4llm). DOCX идёт через тот же разбор.
- **extract**: модель отделяет требования от пояснений и делит составные. Номера пунктов берутся из документа.
- **rules** ищет кодом размытые слова («быстро», «удобно»), заглушки (TBD) и единицы без чисел. Словари лежат в `config/lexicon.yaml`.
- **check_each / check_set**: модель оценивает каждое требование и набор целиком, кандидатов в противоречия подбирает код.
- **verify**: код ищет каждую цитату в документе и проставляет место.

Все словари, пороги и критерии лежат в `config/*.yaml`, промпты — в `reqcheck/prompts/`. Подгонки под конкретный документ в коде нет. Подробнее: [архитектура](docs/03-architecture.md), [технические требования](docs/02-trd.md), [решения (ADR)](docs/08-decisions.md).

## Качество: замерили, а не поверили на слово

Корпус eval — 13 размеченных документов в `tests/fixtures` (MD и PDF, все 14 категорий дефектов, три чистых документа) и документ организаторов с отдельной разметкой в `eval/labels/`. Документ организаторов стоит в отложенной выборке: на нём ничего не настраивали. Конвейер сравнивали с наивным подходом «один промпт на весь документ» с той же проверкой цитат.

Отложенная выборка (6 документов), модель `deepseek/deepseek-v4.1-flash`, 3 повтора. В скобках — минимум и максимум по повторам:

| | Recall | Ложных находок на чистом документе |
|---|---:|---:|
| **Конвейер ReqCheck** | 50 % (43–59 %) | **8** (7–11) |
| Один промпт | 57 % (33–76 %) | 52 (30–72) |

Recall различается в пределах разброса, а шума у конвейера в 6 раз меньше. Кроме того, один промпт в 4 из 18 прогонов обрезался по длине ответа. Отчёт решает, начинать ли разработку, а ложная тревога в нём дорого стоит команде, поэтому основным подходом остался конвейер. Цифры по документам: [`eval/results/2026-11-27-gate.md`](eval/results/2026-11-27-gate.md), решение: ADR-012.

```bash
uv run python -m reqcheck.eval --model openai/gpt-6-luna --dry-run   # оценка стоимости
uv run python -m reqcheck.eval --model openai/gpt-6-luna --both      # конвейер и один промпт
```

| Возможность | Как |
|---|---|
| **Веб-интерфейс** | `uv run python -m reqcheck.server` → http://127.0.0.1:8000. Перетащите файл, выберите модель и получите вердикт, топ исправлений, фрагмент оригинала у каждой находки, отчёт и исходник с пометками. Флажок «Сравнить с одним промптом» показывает оба подхода рядом. Демо без сервера и ключа: `python3 -m http.server 5173 --directory reqcheck/web`, адрес `?demo` |
| **HTTP API** | `/api/v1`, OpenAPI на `/api/v1/docs`: загрузка, поток событий SSE, отчёт в JSON/MD/PDF/DOCX. API защищается токеном `REQCHECK_API_TOKEN`, интерфейс сам его спросит. Подробнее: [docs/04-integration.md](docs/04-integration.md) |
| **Библиотека** | `from reqcheck import validate` → `report = validate("spec.pdf")`, затем `report.save("out/review.pdf")` |
| **PDF с пометками** | `--annotate out/annotated.pdf`: цитата каждой находки выделена в исходном PDF цветом серьёзности, на выделении — комментарий |
| **Word** | DOCX на входе и на выходе (опция `docx`, входит в `uv sync --all-extras` и `requirements.txt`) |
| **Сканы** | `--ocr` распознаёт текст через Tesseract (`brew install tesseract tesseract-lang` или `apt install tesseract-ocr tesseract-ocr-rus`) |
| **CI** | `--fail-on blocker` даёт код выхода 10 при блокирующих дефектах |
| **Docker** | `docker compose up --build`. Ключ берётся из `.env` и в образ не попадает |

## Структура репозитория

```
main.py                  точка входа: python main.py <требования> <отчёт>
reqcheck/                агент: ingest, stages, llm, render, server, web (UI)
reqcheck/prompts/        промпты (версия в первой строке входит в ключ кэша)
config/                  модели и цены, критерии, словари, пороги вердикта
docs/before, docs/after  выданный документ и отчёт агента
docs/                    проектные документы: PRD, TRD, архитектура, интеграция, дизайн, ADR
tests/                   178 тестов без сети, фикстуры и ожидания eval
eval/                    разметка документа организаторов и результаты замеров
```

## Ограничения

- Модель может пропустить дефект: recall на незнакомых документах около 50–60 %. Агент помогает аналитику, но не заменяет ревью.
- Автонумерация Word (1., 1.1) не попадает в текст абзацев DOCX. Номера, набранные текстом («Ф-1.»), сохраняются.
- OCR и Docker-образ проверены частично: в среде разработки не было Tesseract и Docker. Проверены сообщения об ошибках и установка зависимостей из `requirements.txt`.
- Итоговый отчёт сделан версией агента `0b0b506`. Повторный прогон текущей версией сделает новые вызовы модели (см. [`docs/after/README.md`](docs/after/README.md)).
