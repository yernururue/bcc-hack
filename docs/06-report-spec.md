### 3. Проверка каждого требования (ТЗ: проверка каждого)
Для каждого требования — строка характеристик (`✓` ok, `✗` нарушение, `?` неясно) и список находок:

> **R-005** · Часть A › Нефункциональные требования
> «Сервис передаёт push на отправку в течение минуты после получения события.»
>
> | Однозн. | Полнота | Единичн. | Реализ. | Провер. | Коррект. | Необход. | Без реализ. | Соотв. |
> |---|---|---|---|---|---|---|---|---|
> | ✓ | ✗ | ✓ | ✓ | ? | ✓ | ✓ | ✓ | ✓ |
>
> **F-007 · major · Полнота.** Не задана доля событий и условия измерения (нагрузка, перцентиль).
> Цитата: «в течение минуты после получения события»
> Предложение: «Для 99 % событий при нагрузке до N событий/с сервис передаёт push на отправку не позднее 60 с после получения события».

Требования без находок показываются одной строкой «все характеристики соблюдены».

### 4. Проверка всего набора (ТЗ: проверка набора)
Подразделы: противоречия; полнота (чек-лист тем с отметками); дубли; единообразие терминов; ранжирование и трассируемость (IEEE 830); реализуемость в целом. Каждая находка набора ссылается на все затронутые места:

> **F-012 · blocker · Противоречие.** R-002 (Ф-2) ↔ R-011 (Критерии приёмки, строка 2)
> «Месяц определяется по дате совершения покупки» ↔ «Февральский счётчик вырос на 4 000 ₸»

### 7. Итог (ТЗ: итог)

- Правило вердикта приводится явно (из `thresholds.yaml`), чтобы было видно, что решение принял код.

## 3. Категории находок

| `category` | Характеристика | Обычная серьёзность |
|---|---|---|
| `ambiguous` | Однозначность | major |
| `unverifiable` | Проверяемость | blocker для функциональных, major для прочих |
| `incomplete` | Полнота | major или blocker |
| `composite` | Единичность | minor |
| `design_decision` | Независимость от реализации | minor |
| `infeasible` | Реализуемость | major |
| `incorrect` | Корректность | major |
| `unnecessary` | Необходимость | minor |
| `nonconforming` | Соответствие шаблону и стандарту | minor |
| `contradiction` | Непротиворечивость набора | blocker |
| `duplicate` | Отсутствие дублей | minor |
| `terminology` | Единообразие терминов | minor |
| `missing_topic` | Полнота набора | major |
| `traceability` | Трассируемость и ранжирование | minor |

Серьёзность по умолчанию задаётся в `config/thresholds.yaml`, а модель может повысить её, но не выше потолка категории (`max_severity`, ADR-011).

## 4. PDF-оформление

- A4, поля 18 мм, Golos Text 10,5 pt. JetBrains Mono — только для ID (`R-001`, `F-012`) и SHA-256. Якоря, цитаты и текст набраны Golos Text: в нём есть казахские буквы и ₸.
- Цветовые роли как в UI: синий только для ссылок, красный только для `blocker` и вердикта «нельзя».
- Внутренние ссылки: ID требований в нарезке, сводке, вопросах и находках набора ведут к разделу 3, а ID находок в итоге ведут к самим находкам.
- Таблица оценок в разделе 3 имеет 9 колонок одинаковой ширины (52 pt). Она показывается, только если есть находки или не все оценки «соблюдено».
- Колонтитул: имя документа · версия агента · страница N из M.
- Рендер: HTML (`templates/report.html.j2`) → `pymupdf.Story`. Шрифты встраиваются подмножествами (`subset_fonts`), поэтому отчёт на 28 страниц весит около 240 КБ. Глифы ✓ ✗ ↔ берутся из встроенных в MuPDF шрифтов Noto.
