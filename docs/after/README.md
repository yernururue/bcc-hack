**Итог отчёта:** разработку начинать нельзя — 2 блокирующих противоречия; тест-дизайн можно с оговорками, кроме сценариев R-007, R-012, R-014, R-023. 50 требований (7 составных пунктов разделены), 9 нарушений (blocker 2, major 6, minor 1), 1 «неясно», 8 вопросов автору с вариантами ответа и допущением.

Главное, что нашёл агент:
- **F-005, противоречие:** по Ф-2 месяц определяется по дате совершения покупки, а критерий приёмки ждёт, что покупка 31 января в 23:58 попадёт в февральский счётчик.
- **F-006, противоречие:** Ф-3 разрешает один push в месяц, а Ф-4 после смены порога требует push «независимо от истории»; какое правило главнее, не сказано.
- **F-007:** метод сохранения объявлен как GET, а GET не должен менять состояние.
- **F-003:** в описании метода сохранения написано «чтение порога», а метода чтения в документе нет.
- **F-008, F-009, F-010:** типы полей в запросе и ответе расходятся (integer и string); коды 201 и 404 упомянуты в правилах, но не описаны в перечне статусов.

## Независимая проверка

Отчёт проверил свежий ревьюер (Claude Opus 5.5, по подписке, без OpenRouter). Сначала он сам составил список дефектов документа, потом прошёл по отчёту:
- **Ложных находок нет:** все 10 верны по сути, все цитаты дословны на указанных строках. По важности спорны три: F-009 и F-010 скорее minor, F-001 тоже.
- **Оба blocker настоящие,** вердикт «разработку нельзя, тест-дизайн с оговорками» обоснован. Счётчики в md и json сходятся.
- **Пропущено:** ответ 200 с `"result":"ERROR"` против обещанного 400; у Ф-4 нет ветки «новый порог не выше накопленной суммы»; нет метода чтения настроек и «суммы за месяц»; критерии приёмки не покрывают возвраты и границы порога; 403 объявлен, но не возникает; не заполнены версия и согласующие. Полнота по blocker и major — около трети (≈ 4,5 из 14 по списку ревьюера).
- **Вопросы:** ответ на вопрос 8 (тело 404) в документе уже есть; допущение к вопросу 2 выбирает одно из двух спорных правил.
- В таблице нарезки R-023 пересказан неточно («покупка в феврале»), сама цитата верная.

По разметке `eval/labels/organizers.yaml` (19 дефектов, не проверена владельцем) отчёт находит 6 дефектов и ещё 4 указывает на нужном месте с другой категорией.

### Чем этот отчёт лучше предыдущего

Предыдущую версию (Sonnet, агент `0b0b506`, есть в истории git) проверили три таких же ревьюера. Цитаты там тоже были настоящие, но из трёх blocker обоснован был один, F-008, F-009 и F-011 оказались ложными, а противоречие критерия приёмки и Ф-2 агент пропустил. По их выводам исправлены промпты, без подгонки под этот документ ([ADR-015](../08-decisions.md)):
- проверка каждого требования видит весь список требований и не пишет «не задано», если значение есть в другом месте;
- проверка набора подставляет строки критериев приёмки и примеры API в правила;
- исключение из ограничения считается совместимым, только если текст прямо это говорит;
- вопросы не противоречат документу;
- повторы одной проблемы уходят в debug.

## Как получен

Модель `openai/gpt-6-luna` через OpenRouter, версия агента `2fe0d67` (в паспорте, раздел 1). Команды:

```bash
uv run python main.py docs/before/requirements.md docs/after/requirements-review.md --model openai/gpt-6-luna --max-cost 0.03
uv run python main.py docs/before/requirements.md docs/after/requirements-review.pdf --model openai/gpt-6-luna --max-cost 0.01
```

Отчёт написан агентом, вручную не правился. Ответы модели кэшируются, поэтому паспорт показывает только новые вызовы своего запуска:
- Markdown: 2 вызова (+6 из кэша), $0,0021. Шесть ответов из кэша записаны прогоном версии `09e4a0a` (те же промпты extract, check_each и check_set), он стоил $0,0164.
- PDF: собран целиком из того же кэша, поэтому в паспорте «0 вызовов (+8 из кэша), $0».
- Итого реальная стоимость отчёта — $0,019, 10 вызовов.
- Два JSON отличаются только временем запуска и паспортом.
