# 05. Дизайн: интерфейс и дизайн-система

## 1. Бриф

```text
Проектируем: одноэкранный веб-интерфейс агента ReqCheck для аналитиков, QA и жюри (web, десктоп; мобильный — чтобы не ломался).
Цель пользователя: загрузить документ → получить вердикт и отчёт, не читая инструкций.
Тон: точный инструмент, как линейка или штангенциркуль. Спокойно, без «AI-магии».
Главный риск: недоверие к выводам модели → показываем цифры, цитаты и вердикт, который посчитал код.
Запоминающаяся деталь: кнопка «Проверить» сама превращается в индикатор прогресса и потом в вердикт.
Ограничения: белый фон, чёрный текст, синие активные элементы; минимум компонентов; локальные шрифты; без внешних CDN; WCAG AA.
Путь: прямая сборка по этому документу, без вариантов.
```

**Источники решений.** Refero MCP в сессии не авторизован, поэтому живого исследования референсов не было. Решения опираются на бриф владельца (цвета, минимализм, анимации) и на руководства методики Refero по движению, цвету и типографике, а также на её список признаков шаблонного ИИ-дизайна. Если нужен дизайн с опорой на реальные продукты, авторизуйте Refero через `/mcp`, и мы пройдём исследование перед вёрсткой.

## 2. Фиксация направления

```text
Основное направление: монохромный утилитарный инструмент (белый холст, чёрный текст, тонкие линии-разделители, без карточек).
Сохраняем: белый холст; чёрный крупный заголовок без декоративных выделений; синий только на интерактивном; линии 1px вместо карточек; плотные цифры.
Синий — роль: только то, на что можно нажать или что сейчас выполняется (кнопка, фокус, ссылка, активный этап, прогресс).
Красный — роль: только блокирующий дефект и вердикт «нельзя». Больше нигде.
Отвергаем: тёмную тему, индиго/фиолетовый, карточки с тенями, градиенты, эмодзи, декоративную полосу слева, кремовый фон с засечками.
```

## 3. Токены

### Цвет

| Токен | Значение | Роль | Контраст с белым |
|---|---|---|---|
| `--bg` | `#FFFFFF` | Холст | — |
| `--fg` | `#0A0A0A` | Основной текст | 19,8:1 |
| `--fg-muted` | `#6B6B6B` | Подписи, метаданные | 5,33:1 |
| `--line` | `#E6E6E6` | Разделители | декоративный |
| `--line-strong` | `#C8C8C8` | Рамки полей ввода, пунктир зоны загрузки, пустой кружок этапа | декоративный |
| `--accent` | `#0052FF` | Кнопка, ссылка, фокус, прогресс, активный этап | 5,75:1 |
| `--accent-hover` | `#0047E1` | Наведение | 7,03:1 |
| `--accent-tint` | `#EEF3FF` | Фон зоны загрузки при перетаскивании, выделение строки | декоративный |
| `--danger` | `#C62828` | Только `blocker` и вердикт «нельзя» | 5,62:1 |

Зелёного нет. Успех обозначается чёрным текстом и синей галочкой.

### Типографика

- Текст: **Golos Text** (ParaType, SIL OFL; интерфейсный гротеск, спроектированный под кириллицу). Фолбэк: `system-ui, sans-serif`.
- Цифры и ID: **JetBrains Mono** (SIL OFL). Используется для счётчиков, ID (`R-001`, `F-012`), якорей и цен.
- **Цитаты из документа набираются Golos Text, а не моноширинным.** Проверено 2026-11-25: в Golos Text есть все казахские буквы (ә ғ қ ң ө ұ ү һ і) и знак ₸, а в JetBrains Mono нет ә ғ қ ң ұ һ. Цитата в кавычках «…» без рамок и полос.
- Шрифты лежат локально: `reqcheck/web/fonts/` (woff2, подмножества latin, latin-ext, cyrillic, cyrillic-ext из @fontsource 5.3.0, подключение — `reqcheck/web/fonts.css`). Для PDF понадобятся TTF в `reqcheck/render/fonts/`.

| Токен | Размер / высота строки | Начертание | Где |
|---|---|---|---|
| `--t-display` | 40/44 | 600, `letter-spacing: -0.02em` | Заголовок экрана, вердикт |
| `--t-title` | 20/28 | 600 | Заголовки блоков |
| `--t-body` | 16/24 | 400 | Текст |
| `--t-small` | 13/18 | 400, `--fg-muted` | Подписи, метаданные |
| `--t-mono` | 14/20 | 400, mono, `tabular-nums` | ID, якоря, счётчики, цены |
| `--t-stat` | 48/48 | 500, mono, `tabular-nums` | Крупные цифры сводки |

Заголовки — `text-wrap: balance`.

### Отступы, форма, глубина

- Сетка 8px: `--s-1: 4px`, `--s-2: 8px`, `--s-3: 16px`, `--s-4: 24px`, `--s-5: 40px`, `--s-6: 64px`.
- Колонка контента `max-width: 640px`, выравнивание по левому краю, отступ слева `clamp(16px, 8vw, 120px)`.
- Радиус: `--r: 6px` для кнопок и полей; зона загрузки `--r-lg: 10px`. Других радиусов нет.
- Теней нет. Глубину задают линии 1px `--line` и белое пространство.

### Движение

```css
--d-fast: 120ms;      /* наведение, нажатие, фокус */
--d-base: 200ms;      /* смена состояния */
--d-slow: 320ms;      /* появление блоков, морфинг кнопки */
--ease-out: cubic-bezier(0, 0, .2, 1);
--ease-in: cubic-bezier(.4, 0, 1, 1);
--ease-emph: cubic-bezier(.2, 0, 0, 1);
--dist-sm: 4px; --dist-md: 8px;
```

Ничего не длится дольше 500 мс, кроме прогресса, который привязан к реальным событиям. `transition: all` не используем. Все анимации прерываемы.

## 4. Компоненты (всего 7)

| Компонент | Состояния | Детали |
|---|---|---|
| **Button** | `primary`, `secondary`, hover, active, focus, disabled, `loading→progress` | Primary: синий фон, белый текст, высота 44px. Secondary: текст синий, без фона, подчёркивание при наведении. Нажатие: `scale(.98)` за 90 мс |
| **DropZone** | пусто, перетаскивание, ошибка формата | Пунктир 1px `--line` → при перетаскивании сплошная синяя рамка и `--accent-tint`. Ошибка: короткое покачивание 200 мс + строка `--danger` под зоной |
| **FileChip** | файл выбран, удаление | Имя файла (mono), размер, число страниц; крестик. Появляется морфингом из DropZone |
| **Select** | закрыт, открыт, фокус | Нативный `<select>` с нашим стилем: модель + цена за прогон («≈ $0,02») |
| **StageList** | ожидание, активен, готово, ошибка | 8 строк, только названия этапов. Активный: синяя точка пульсирует (opacity, 1,2 с). Готов: галочка рисуется обводкой за 200 мс. Пояснение справа — только при ошибке. Виден только во время прогона |
| **Stat** | счёт | Крупная цифра (`--t-stat`) с подписью. Значение отсчитывается от 0 за 400 мс |
| **FindingRow** | обычная, раскрыта | ID + серьёзность + короткая формулировка; раскрытие показывает цитату и якорь. Без карточек: строки через разделитель |

Разделение блоков — линия 1px и отступ `--s-5`. Карточек нет.

## 5. Экран и состояния

Один экран, один вертикальный поток. Каждое следующее состояние раскрывается ниже предыдущего, ничего не перескакивает.

```
ReqCheck
─────────────────────────────────────────────────────────────
Проверка требований

┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐
  Перетащите PDF или Markdown
  или выберите файл
└ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘

Модель   [ openai/gpt-6-luna · ≈ $0,02 ▾ ]

[ Проверить ]
```

| Состояние | Что видно | Переход |
|---|---|---|
| **S0 Пусто** | Заголовок, DropZone, Select, кнопка неактивна | — |
| **S1 Файл выбран** | DropZone сворачивается в FileChip; кнопка становится активной | Морфинг высоты зоны 320 мс + проявление чипа |
| **S2 Прогон** | Кнопка растягивается на ширину колонки и становится полосой прогресса; под ней StageList; FileChip и Select заблокированы | Ширина кнопки 320 мс `--ease-emph`; над полосой — название этапа слева и «3 / 8» справа |
| **S3 Готово** | Список этапов сворачивается и исчезает; полоса сжимается в строку вердикта; появляются три Stat (требований / нарушений / блокирующих), топ-5 исправлений (FindingRow), кнопка «Скачать отчёт PDF» и вторичная «JSON» | Вердикт проявляется с подъёмом на 8px; Stat отсчитываются по очереди с шагом 60 мс |
| **S4 Ошибка** | Строка ошибки под полосой и кнопка «Повторить»; этап с ошибкой помечен | Покачивание полосы 200 мс |

Вердикт — самая крупная надпись экрана после прогона:
- «Можно начинать разработку» — `--fg`;
- «Нельзя начинать: 3 блокирующих дефекта» — `--danger`.

## 6. Хореография анимаций

| Момент | Анимация | Длительность | Зачем |
|---|---|---|---|
| Наведение на кнопку | цвет фона | 120 мс | отклик |
| Перетаскивание файла | рамка из пунктира в сплошную, фон tint | 120 мс | отклик |
| Файл принят | зона → чип (View Transitions API, фолбэк — высота + opacity) | 320 мс | непрерывность |
| Старт | кнопка → полоса прогресса | 320 мс | непрерывность: действие пользователя становится процессом |
| Этап завершён | галочка рисуется `stroke-dashoffset`; полоса прибавляет долю | 200 мс | обратная связь |
| Готово | полоса → вердикт, затем каскад Stat и строк | 320 мс + 60 мс шаг | иерархия: сначала ответ, потом детали |
| Раскрытие находки | высота + opacity | 200 мс | непрерывность |

`prefers-reduced-motion: reduce`: морфинги заменяются проявлением 150 мс, счётчики сразу показывают итог, пульсация выключена.

## 7. Доступность

- Контраст всех текстов ≥ 4,5:1 (см. таблицу цветов).
- Фокус: кольцо 2px `--accent` с отступом 2px, видно на любом фоне.
- DropZone — это `<label>` над `<input type="file">`, работает с клавиатуры и экранного диктора.
- Прогресс — `role="progressbar"` с `aria-valuenow`; смена этапа объявляется через `aria-live="polite"`.
- Вердикт объявляется через `aria-live="assertive"` один раз.

## 8. Тексты интерфейса

Коротко, глаголом, без восклицаний. Технических подписей на экране нет: версия агента, стандарты, время этапов, число вызовов и стоимость прогона живут в паспорте отчёта, а не в интерфейсе. Цена модели видна один раз — в списке моделей.

| Место | Текст |
|---|---|
| Заголовок | Проверка требований |
| DropZone | Перетащите PDF или Markdown / или выберите файл |
| Кнопка | Проверить |
| Прогресс | Проверка каждого требования · 3 / 8 |
| Скачать | Скачать отчёт PDF · JSON |
| Ошибка формата | Нужен PDF, Markdown или TXT |
| Ошибка бюджета | Достигнут лимит $0,50. Отчёт неполный |

## 9. Реализация

- Без сборщика: `web/index.html`, `app.css` (все токены в `:root`), `app.js` (ванильный JS), `demo.js`. Отдаётся FastAPI как статика.
- UI работает через один из двух адаптеров с общим интерфейсом `listModels()`, `loadExample()`, `run(file, model, onEvent)` → вид результата, `download(kind)`, `dispose()`: `http.js` (по умолчанию, `/api/v1`, прогресс через `EventSource` на `/checks/{id}/events`, результат из `/checks/{id}/summary`) и `demo.js` (`?demo`, фиктивные данные без сервера; `?demo&fail` — сценарий ошибки).
- Запуск: `uv run python -m reqcheck.server`, затем http://127.0.0.1:8000. Без сервера: `python3 -m http.server 5173 --directory reqcheck/web` и `?demo`.
- «Попробовать на примере» загружает `reqcheck/web/example.pdf` (копия фикстуры `tests/fixtures/defects.pdf`).
- Если проверка идёт с ошибкой на этапе LLM, но отчёт собран, под кнопкой скачивания пишется «Отчёт неполный: …».
- Прогон не должен зависеть от `requestAnimationFrame`: во фоновой вкладке кадры не рисуются. Анимации — да, логика — нет.
- Никаких внешних запросов: шрифты и иконки (3 SVG: файл, галочка, крестик) лежат локально.

## 10. Проверка перед сдачей

- [ ] Синий есть только на интерактивном и прогрессе.
- [ ] Красный есть только у блокирующих дефектов и вердикта «нельзя».
- [ ] Нет карточек, теней, градиентов, эмодзи.
- [ ] Все анимации на токенах, ≤ 500 мс, есть вариант reduced-motion.
- [ ] Клавиатура: Tab проходит зону загрузки → модель → кнопка → скачивание.
- [ ] Ширина 375px: ничего не обрезано, нет горизонтальной прокрутки.
