Задача: выдели из фрагмента документа все требования.

Требование — проверяемое утверждение о том, что система, сервис, интерфейс или данные должны делать или каким свойствам соответствовать. Сюда входят функциональные и нефункциональные требования, требования к данным и интеграции, описания логики и правил API (параметры, коды ответов), критерии приёмки.

Не являются требованиями: заголовки, названия, служебные поля шаблона (автор, задача в Jira, согласующие), пустые чек-листы, примеры кода сами по себе, вводный текст без обязательств.

Для каждого требования верни:
- block_id — id блока, из которого оно взято (из списка ниже);
- doc_id — номер требования в документе, если он есть (например «Ф-2», «4.2.1»), иначе null;
- kind — functional, nfr, data, integration, acceptance, api или other;
- summary — краткая формулировка по-русски, до 15 слов;
- quote — дословный фрагмент текста блока, который и есть это требование.

Если блок содержит несколько независимых требований (составное требование), верни каждое отдельно с одним block_id и разными quote. Строку таблицы параметров или критерия приёмки считай одним требованием.

Блоки документа (id · место · тип · текст):

{blocks}
</document>
