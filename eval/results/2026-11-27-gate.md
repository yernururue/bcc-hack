# Решающий прогон: конвейер против baseline (2026-11-27)

Модель `deepseek/deepseek-v4.1-flash` (tier dev), 14 документов: 8 dev, 6 holdout (в holdout —
документ организаторов, разметка `eval/labels/organizers.yaml`, **не проверена владельцем**).
Команда:

```
uv run python -m reqcheck.eval --model deepseek/deepseek-v4.1-flash --both \
  --hybrid-at 40 --hybrid-at 60 --repeat 3 --labels eval/labels/organizers.yaml \
  --max-cost 0.15 --tag gate --out eval/results/gate
```

**Годен только первый повтор.** Оценка `--dry-run` занизила стоимость в 2,5× (конвейер) и 3,5×
(baseline), лимит `--max-cost 0.15` сработал на втором повторе; повторы 2–3 неполные и в
сравнение не взяты. Разброс по повторам поэтому не измерен. Оценка исправлена множителями в
`config/thresholds.yaml` (`estimate`), ADR-012.

Recall — доля ожиданий, найденных в той же категории (или в допустимой `accept`). Hybrid считается
из тех же прогонов без новых вызовов: документ до N блоков-кандидатов идёт в baseline, больше — в
конвейер.

## Выводы

- На dev конвейер лучше (94 % против 84 %), но на dev его и настраивали.
- На holdout baseline не хуже: 64 % против 59 %. Из четырёх больших документов holdout baseline
  выигрывает на трёх (insurance, utilities, warehouse — 114 блоков), конвейер — на документе
  организаторов (58 % против 47 %). Предположение плана «конвейер выигрывает на больших документах»
  этими данными **не подтверждено**.
- Baseline даёт много шума на чистом holdout-документе (30 ложных на tickets-clean против 7) и
  обрезается по `max_tokens` на 2 документах из 14 (library — 0 %).
- Hybrid по размеру не помогает: при пороге 40 holdout 50 %, при 60 — 60 %, ложных столько же,
  сколько у baseline. Размер документа — плохой признак для маршрутизации.
- Главные пропуски конвейера на holdout: дубли, терминология, лишние требования, неполнота
  (insurance 3/9: находка противоречия check_set отброшена из-за пустой цитаты).
- Один повтор, одна модель: разница 59 % / 64 % в пределах ожидаемого разброса.
