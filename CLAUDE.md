# ReqCheck — правила для агентов

Агент статического ревью требований (хакатон BCC-HUB). Проектные документы: `docs/` (начинать с `docs/README.md`). ТЗ организаторов (только чтение): `../ai-requirements-validator-task`.

## Обязательно
- Источник правды по требованиям — `docs/01-prd.md` и `docs/02-trd.md`; решения — `docs/08-decisions.md`. Меняешь решение — обнови ADR.
- API библиотек не писать по памяти: сверяться с документацией или исходником установленной версии.
- Никаких привязок к конкретному тестовому документу: эвристики, словари, пороги — только в `config/*.yaml`.
- LLM только через порт `LLMClient` (OpenAI-совместимый, по умолчанию OpenRouter). Вердикт и счётчики считает код.
- Находка без проверенной кодом цитаты в отчёт не попадает.
- Бюджет LLM $1–2, деньги владельца: для тестов и разработки только модели `tier: dev`/`cheap` из `config/models.yaml`; `strong` — только с явного согласия владельца. Кэш включён; без нужды `--no-cache` не запускать. Юнит-тесты сеть не трогают.
- UI — по `docs/05-design.md`: синий только на интерактивном, красный только для blocker, без карточек и теней.

## Процесс
- Python 3.12, `uv`. Тесты: `uv run pytest -q`, линтер: `uv run ruff check .`. Зависимости: `uv export --no-hashes --no-dev -o requirements.txt`.
- Маленькие коммиты в стиле conventional commits после каждого этапа из `docs/07-plan.md`; перед коммитом тесты зелёные.
- Не коммитить `.env`, ключи, `.cache/`, `out/`.
